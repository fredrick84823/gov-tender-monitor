規則實驗室

左邊改規則，右邊即時重跑。四層漏斗依比例繪製 —— 那個坍縮本身就是重點：白名單砍掉一半，兩路命中再砍到 3.5%，排除清單收尾。

情境一：關掉 3 條校外教學排除詞

把 戶外教育活動 / 校外教學 / 戶外教育 三條關掉。這三條目前擋下 16 筆國中小校外教學案 —— 它們都命中了 C 組「活動」關鍵字，卻不是媒體採購。證明排除清單是必要的。

情境二：關掉「畢業紀念冊」

只關這一條。回來的 3 筆全部走路 A —— 是政府自己把它們歸類為 勞務類875-攝影服務。排除清單能蓋掉官方分類，也就是它可能訂得太寬：畢冊確實是攝影採購，客戶不想看而已。這個張力沒有正確答案，只能問客戶。

過程中發現一件規格沒提的情況：同一個標案在同一天可能同時有「招標公告」與「無法決標公告」兩筆（8/17 有兩件）。公告類型白名單正確地只留下招標那筆 —— 這不是巧合，是白名單放在漏斗第一層的副作用。

npm run verify 把這件事變成可重複執行的測試，不是一次性的人工核對。方法本身見下一節。

作業系統排程（cron / launchd）—— 這是可行的做法

其他六種機制：可行的與各自的限制逐項對照官方文件查證
機制可行？限制
claude -p + OS 排程可行但真正在排程的是 cron；且長效 token 效期一年，到期後排程開始失敗。
/schedule routines可行唯一不需要你的機器開著。但跑在雲端、每次重新 clone repo，xlsx 落在雲端不在本機磁碟，也讀不到未 commit 的收件人清單。
/loop不行session 內計時器，終端機關掉就停。16:10 筆電在睡 → 不執行，也不報錯。
CronCreate不行session-only、in-memory、7 天自動失效（durable 參數存在但標示無效）。
hooks不行30 幾種事件沒有一個是時間驅動的。
自訂 slash command不行只在訊息開頭被辨識，只有人打字才會觸發。

更根本的原因：這條管線裡沒有 LLM。select、enrich、buildWorkbook 都是純函式，89 條測試固定其行為，同一天的輸入必然得到同一份輸出 —— 沒有需要判斷的環節。
