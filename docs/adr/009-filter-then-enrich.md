# 009. 先粗篩再細查，不對全天資料細查

**狀態**：已實作　**決策者**：我

## 背景

`預算金額` 與 `截止投標` 不在當日清單回應裡，必須逐案再打一次 API。

匿名呼叫的速率限制實測約「7 秒 10 次」，超過即 429，**且回應沒有 `Retry-After`
標頭**，只能盲目退避。一天有 1787 筆公告。

## 決策

管線順序固定為：公告類型白名單 → 分類解析 → 兩路命中 → `filename` 去重 →
排除清單 → **才**逐案細查。

細查只打在收斂後的結果上。

## 理由

實測數字（2026-08-17）：

```
1787  當日全部公告
 897  過公告類型白名單    ← 一步砍掉 50%
  62  兩路命中並去重      ← 只剩 3.5%
  35  扣掉排除清單
```

全天細查需要 1787 次請求，在每秒一次的限速下約 30 分鐘，且必然多次撞上 429。
收斂後只需 35 次，約 35 秒。

公告類型白名單放第一步是因為它砍掉最多 —— 決標、無法決標、定期彙送、財物出租
一次全部出局。

## 後果

- 總耗時 1 分 17 秒，其中細查佔約 35 秒，是主要瓶頸但完全可接受。
- client 內建節流（序列化 + 最小間隔 1 秒），正常每日查詢不會觸發限制。
- 測試釘住這個行為：`test/run-daily-report.test.js`「細查只打在已收斂的結果上」
  —— 餵 500 筆雜訊 + 1 筆命中，斷言只發出 1 次細查請求。
- 建議向開放文化基金會申請 API token 以解除匿名限制，已列入客戶問題清單。
