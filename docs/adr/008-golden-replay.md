# 008. 可重現性用黃金檔離線重播，比對內容不比對位元組

**狀態**：已實作　**決策者**：我

## 背景

任務二要求「這套流程能複製到別人的硬體環境中運行，並取得一樣的 Excel」。

「一樣」需要能驗證，否則只是一份安裝說明。

## 決策

`npm run verify`：用已擷取的真實資料（`web/data/demo-data.json`，2026-08-17
全天 1787 筆 + 62 筆細查）離線重播完整流程，把產出的 workbook 抽成內容快照，
逐列逐欄比對 `test/golden/20260817.json`（87 列）。

不比對檔案位元組。

## 理由

- **離線**：可重現性不該依賴網路。同一份輸入必須在任何機器上得到同一份輸出。
  走 API 的話，資料源改版或當天狀態不同就會失敗，那驗證的是 API 不是我們的程式。
- **比內容不比位元組**：xlsx 是 zip，內含建置時間戳與 docProps，逐位元組相同
  在實務上不可能。這也是規格「與 ad-report byte-identical」做不到的同一個原因。
- 產出時間那一行會正規化掉再比對。

## 後果

- 「別人的機器產出是否相同」變成一個**會過或會失敗的測試**。
- 改動規則或版型後 `verify` 一定會失敗（它比對舊基準）。確認新結果正確後執行
  `npm run verify:update` 更新黃金檔 —— 這是刻意的摩擦，讓基準變更成為一個明確動作。
- 環境差異另由 `npm run doctor` 檢查六項前提：Node 版本、相依套件、寫入權限、時區、
  中文字型、API 連通性。每一項都是實際踩過的坑，不是形式檢查。
