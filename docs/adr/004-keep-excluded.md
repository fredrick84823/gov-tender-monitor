# 004. 被排除的標案保留並輸出「已排除」分區

**狀態**：已實作　**決策者**：我（規格與客戶範本都沒有這個東西）

## 背景

規格第八節自承 38 條排除清單是「客戶回饋『這件不該出現』就加一條」累積出來的，
並說「這是改最多版的地方」。

問題在於這個回饋機制**只有單向**：排除詞是對整個標案名稱做字串包含比對，
而這些詞描述的是「採購標的」。標題裡常同時出現場地名與真正的標的，因此會誤殺。
而被誤殺的案子**無聲消失**，客戶看不到，也就永遠不會反映 —— 清單只會越來越嚴。

## 決策

`select()` 不丟棄被排除的標案，而是回傳 `{ selected, excluded }`。
Excel 末尾增加「已排除」分區，列出每筆被哪一條詞擋下、原本會命中哪幾組關鍵字，
並保留官網連結。依排除詞分組排序，同一條詞擋下的案子排在一起。

## 理由

讓誤殺**可被發現**。依排除詞分組是刻意的：一眼就能判斷某條詞是不是訂得太寬。

## 後果

2026-08-17 的真實資料驗證了這個設計的價值：

- 27 筆被排除中有 **16 筆是學校校外教學／戶外教育**（三條詞），印證清單確實必要。
- 但【畢業紀念冊】擋掉的 3 筆**全部是路 A 命中** —— 也就是政府自己把標的分類編為
  871 廣告服務 / 875 攝影服務，然後排除清單因為標題四個字把它們否決了。
  **排除清單正在推翻政府的官方分類。**

第二點是這個分區存在才看得見的。若照規格直接丟棄，沒有人會發現。

排除的順序也因此固定為**最後一步**：先判定命中、去重，最後才套排除清單，
這樣每筆被擋下的案子都還帶著「原本會命中哪幾組」的資訊。
