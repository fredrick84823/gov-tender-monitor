# 005. 輸出版型以客戶範本為準，而非規格文字

**狀態**：已實作，待客戶確認　**決策者**：我

## 背景

客戶提供了一份實際使用中的輸出範本（`gov_tenders_20260817.xlsx`）。
它與規格第四節的文字描述有五處實質衝突：

| 項目 | 規格文字 | 客戶範本 |
|---|---|---|
| 分頁 | 一大類一分頁 | 單一分頁 |
| 每筆列數 | 兩列一筆 | 一列一筆 |
| 分區依據 | 標的分類大類 | 搜尋路徑（大類 + A/B/C/D 組關鍵字） |
| 命中標示 | 四組色碼 | 無色碼，底色僅為斑馬紋 |
| 日期 | 民國年 | 西元 |

規格第四節內部還自相矛盾：「版型」句與「欄位」句列出兩組不同的欄位，兩者都不等於範本。

## 決策

以範本為準。並照範本的實際樣式實作（品牌色 `#873222`、表頭 `#66272A`、
斑馬紋 `#F7F2F0`、微軟正黑體、日期欄用 Arial）。

## 理由

範本是客戶手上真正在用的東西。文字描述可能是早期版本或轉述失真，
但範本是他們每天實際打開的檔案。

## 後果

- 一案命中多組時，照範本在每一區各出現一次；標題的「共 N 筆」算去重後的數量。
  這也解答了規格沒說的「一案命中多組怎麼標色」——不標色。
- **但範本的排除清單顯然是舊版**：範本裡仍有「115學年度學生露營活動」這類
  38 條清單要擋的雜訊，表示範本產出時間早於清單定案。
  **那範本的版型會不會也已過時？** 這是客戶問題清單第 3 題，尚未回覆。
- 規格要求「與 ad-report byte-identical」在技術上不可能（xlsx 是 zip，含建置時間戳），
  已建議改寫驗收條件為「共用同一套樣式模組，外觀一致」。
