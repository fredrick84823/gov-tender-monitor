# 002. 去重鍵用 `filename`，不用 `unit_id + job_number`

**狀態**：已實作　**決策者**：我（推翻客戶規格）

## 背景

規格第二節明寫「兩路**聯集去重**（`unit_id` + `job_number`）」。

實測 API 後發現：`unit_id + job_number` 是**案件鍵**，不是公告鍵。同一個標案的原公告
與更正公告共用同一組值。實例（中央研究院 `2.1` / `BTRC11503042E`）：

```
20260907  TIQ-11-71107895  公開取得報價單或企劃書公告
20260908  TIQ-12-71107895  公開取得報價單或企劃書更正公告
```

## 決策

以 `filename` 作為公告唯一鍵去重。

## 理由

照規格實作，每一筆更正公告都會被判定為「與原公告重複」而丟掉。更正公告常帶截止日
延期、廠商資格變更這類關鍵異動 —— 這不是效能問題，是**客戶會漏掉重要資訊**。

而且這個錯誤是靜默的：客戶只會看到少了一筆，不會知道為什麼。

## 後果

- 同一案件的原公告與更正公告都會出現，更正的那筆標案名稱前綴 `【更正】`。
- 跨日重複仍未處理 —— 更正公告通常隔天才發，客戶昨天已看過原公告。要做到「只寄真正
  沒看過的」需要跨日的已寄送紀錄，規格完全沒有這部分設計。列為待客戶確認事項。
- 測試：`test/select.test.js`「原公告與更正公告共用 unit_id+job_number，但兩者都必須留下」。
