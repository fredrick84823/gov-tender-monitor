# 007. 以客戶範本作為 ground truth 驗證零漏報

**狀態**：已驗證　**決策者**：我

## 背景

這套系統要取代人工查詢。人工漏一件沒人怪，機器漏一件就沒人敢信。
所以「零漏報」是隱含的驗收標準 —— 但規格通篇沒有任何驗收機制。

問題是：**拿什麼當基準？** 用自己的實作產生期望值，等於自己出題自己改，
只能驗證程式沒變、不能驗證程式正確。

## 決策

客戶提供的範本正好是 2026-08-17。用**同一天的真實資料**跑完整流程，
抽出兩份 Excel 的標案名稱做集合比對。

## 結果

```
範本 30 筆 ｜ 我們命中 35 筆 ｜ 我們排除 27 筆

範本有、我們漏掉      0 筆   ← 唯一真正要緊的數字
範本有、我們也有     30 筆
我們有、範本沒有      5 筆   ← 全部溯源到同一個公告類型（見 ADR 003）
```

## 理由

ground truth 必須來自實作之外。客戶手動查出來的那份 Excel 是唯一的外部基準。

## 後果

- 零漏報成立，而且多出的 5 筆能完整溯源到單一原因，不是隨機雜訊 —— 這讓差異變成
  一個可以拿去問客戶的具體問題，而不是一個要調參數的模糊誤差。
- 比對過程中發現一個規格沒提的情況：**同一標案當日可能同時有招標公告與無法決標公告**
  （8/17 有兩件）。公告類型白名單正確地只留招標那筆。這是比對時才發現的。
- 這個驗證是一次性的（只有一天的範本）。長期要維持零漏報，需要上線初期的平行期
  比對，已列入客戶問題清單。
