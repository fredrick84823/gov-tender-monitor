# 003. 分類為 null 的公告放行關鍵字路徑

**狀態**：已實作，並建議客戶修改規格　**決策者**：我

## 背景

規格的兩條命中路徑都限定「勞務類」。但實測發現「公開徵求廠商提供參考資料公告」
（規格白名單中的 10 種之一）的 `brief.category` 是 `null` —— API 對這類公告
不提供標的分類，細查也只有 15~18 個欄位，**沒有標的分類、沒有預算、沒有截止投標**。

於是產生矛盾：規格要求收這種公告，但無從判定它是否為勞務類。

## 決策

`category` 為 `null` 時，放行關鍵字路徑（路 B），三個缺失欄位如實印「未公開」。

## 理由

嚴格套用「限勞務類」會把整個類型丟掉，等於漏報一整類規格明文要收的公告。
在「可能多收雜訊」與「必然漏掉一整類」之間，選前者 —— 多收的看得到，漏掉的看不到。

## 後果

2026-08-17 的實測顯示這個決策帶來 5 筆雜訊（財物購置、系統維護、戶外教學），
**而客戶自己的範本裡這個類型是 0 筆**。

因此進一步建議客戶**從白名單移除這兩種公告類型**。移除後命中數從 35 收斂到 30，
與客戶範本完全一致。見 `docs/client-questions.md` 第 4 題。

這是一個「先照規格做、拿數據再回頭建議改規格」的例子。
